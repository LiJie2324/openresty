## Fix #21 (commit e79056b, tag v1.31.1.1-alpha13): 修复 sed 替换模式

### 问题
alpha12 CI 失败：`ERROR: failed to patch bundle/nginx-1.31.1/auto/lib/openssl/make`

### 根本原因
之前在 build-win32.sh 里的 sed 命令试图匹配带变量的格式：
```
OPENSSL_CONFIG_CMD="./config"
OPENSSL_CONFIG_OPTS=""
```
但这些变量是我之前修改本地磁盘文件时加入的。
原版 nginx-1.31.1/auto/lib/openssl/make 中**没有这些变量**，实际内容是：
```
&& ./config --prefix=$ngx_prefix no-shared no-threads $OPENSSL_OPT \
```

所以 sed 找不到匹配内容，grep 验证 `Configure.*mingw64` 失败，构建退出。

### 修复
将 sed 改为直接替换原版内容：
```bash
sed -i 's|\&\& \./config --prefix=|\&\& ./Configure mingw64 --prefix=|' "$NGINX_MAKE"
```
这匹配了原版 nginx tarball 中的实际行，一步到位替换为 `./Configure mingw64`。

## Fix #22 (commit 0fb3c4e, tag v1.31.1.1-alpha14): 修复 OpenSSL Configure 使用错误 Perl

### 问题
alpha13 CI 失败：
```
Configuring OpenSSL version 3.5.5 for target mingw64
Failure! Makefile wasn't produced.
This perl implementation doesn't produce Unix like paths
This Perl version: 5.38.5 for MSWin32-x64-multi-thread
```

### 根本原因
OpenSSL `./Configure` 需要产生 Unix 路径的 Perl（`/usr/bin/perl`，输出正斜杠），
但找到的是 MinGW perl（`MSWin32`，输出反斜杠）。

之前的 `PATH="/usr/bin:$PATH" ./configure` 只在 nginx `./configure` 调用时生效，
不影响 `make` 子进程（OpenSSL Configure 是在 `make` 阶段触发的）。

### 修复
在 `build-win32.sh` **顶部** 加 `export PATH="/usr/bin:$PATH"`，全局生效，
覆盖所有后续子进程，包括 `make` 触发的 OpenSSL `./Configure`。

### 历史教训总结
- `.gitignore` 有 `openresty-*`，`openresty-1.31.1.1/bundle/` 下的文件永远不能直接 commit
- CI 每次从原始 tarball 解压 nginx，本地修改毫无意义
- 唯一可靠的途径是在 `build-win32.sh` 里用 `sed` 在 tarball 解压后、configure 前动态 patch
- sed 的替换模式必须精确匹配**原版文件内容**，而不是本地被修改过的版本
- 用 `curl | tar xzO` 验证 tarball 中的原版文件内容很重要！

## Fix #23 (commit 622b8ab, tag v1.31.1.1-alpha15): 修复 make install 缺少 resty.index

### 问题
alpha14 CI 几乎完全成功——nginx、OpenSSL（mingw64 目标）、LuaJIT 和所有
lua-resty-* 模块都编译安装成功，但最后一步失败：
```
cp /d/a/openresty/openresty/openresty-1.31.1.1/build/resty.index ...
cp: cannot stat '.../build/resty.index': No such file or directory
make: *** [Makefile:37: install] Error 1
```

### 根本原因
CI workflow `build-win64.yml` 第 44 行设置 `SKIP_RESTYDOC: 1`，
这使 `mirror-tarballs` 跳过所有 `restydoc-index` 调用。
`restydoc-index` 负责生成 `resty.index`，跳过意味着该文件从未被创建。
但 `util/configure` 生成的 Makefile 仍然包含 `cp build/resty.index`，
导致 `make install` 失败。

### 修复
在 `build-win32.sh` 中 `make install` 之前添加：
```bash
mkdir -p build
touch build/resty.index
mkdir -p build/pod
```
这确保文件存在（即使是空文件），满足 Makefile 中 `cp` 的要求。

## Fix #24 (commit dc6d801, tag v1.31.1.1-alpha16): 修复 mirror-tarballs 合并冲突

### 问题
alpha15 CI 的 "Prepare bundle" 步骤失败：
```
./util/mirror-tarballs: line 1170: syntax error near unexpected token `<<<'
./util/mirror-tarballs: line 1170: `<<<<<<< HEAD'
```

### 根本原因
之前执行了 `git merge origin/master`（merge commit c49573d），合入了上游
commit 4eb3c73 的并行 restydoc-index 处理。但合并留下了三处未解决的
冲突标记（`<<<<<<< HEAD`），导致 shell 语法错误。

### 修复
解决 `util/mirror-tarballs` 中的三处冲突：
1. 保留上游的 conditional `git pull`（`MIRROR_SKIP_NGINX_DOCS_UPDATE`）
2. 保留 HEAD 的 `SKIP_RESTYDOC` 检查 + 上游的并行 `restydoc_dirs` 处理
3. 将 `curdir=$PWD` 移到 `if` 块之前，确保 `SKIP_RESTYDOC=1` 时也有值

### 教训
- merge 后一定要检查是否有未解决的冲突标记（`grep -rn '<<<<<<<' .`）
- 冲突标记在 shell 脚本中会导致语法错误，使整个脚本无法执行
